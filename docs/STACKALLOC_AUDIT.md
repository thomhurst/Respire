# Package local initialization audit

The package assemblies listed in `Directory.Build.props` opt out of implicit local zeroing through the shared `[module: SkipLocalsInit]` attribute. Tests, benchmarks, samples, tools, and `Respire.Analyzers` do not opt out. Explicit initialization is unchanged. This audit covers both supported framework branches; the UTF-8 decoder is unchanged.

## Review contract

Each table row identifies one active explicit or implicit `stackalloc`, in source order within its file. Frameworks are comma-separated. The fingerprint is SHA-256 of the enclosing member's Roslyn token kinds and exact token text, separated by newlines. It includes initialization, consumers, and branches, but ignores comments and whitespace. Moving a site, replacing a same-count allocation, or changing its enclosing member requires review. Two sites in one member still require separate justifications.

`StackAllocationAuditTests` compares the complete source inventory against these rows using each package's SDK-evaluated symbols for Debug and Release on both frameworks, including Polyfill's reference-dependent feature symbols. Identical sites across configurations share one review; different active member bodies require different fingerprints. Shared package source and NuGet content compile items are scanned too: imported source inherits the consuming module's policy. There are 29 repository sites and two imported .NET 8 Polyfill sites. To update a failing row, inspect the changed method and every helper it calls, verify initialization and read bounds on success and failure, then copy the reported fingerprint and update that site's explanation. Never bulk-regenerate approved rows to make a failure disappear. New packages and framework branches require the same audit.

**Source matching cannot prove data-flow safety.** The guard detects changed source and missing, duplicate, or stale review entries. It cannot determine whether prose is correct, whether a called helper's contract has changed, or whether externally supplied memory is mutated concurrently in violation of its lifetime contract. Helper changes still require human review. This document records the checked contracts, not a claim that matching hashes prove memory safety.

## Performance acceptance

`scripts/Verify-PackageLocalInitialization.ps1` checks the compiled module attribute in both framework outputs of every package and its absence in every other solution assembly. It also requires uninitialized local bodies in package outputs, retains body counts in its report, and rejects uninitialized local bodies in excluded assemblies. `LocalInitializationTests` checks a real package method and an excluded test method with stack storage on each framework. Compiler-synthesized helpers may still retain `initlocals`, such as `<>z__ReadOnlySingleElementList<T>.Enumerator.MoveNext`. More initialization in that helper is safe and does not mean the module attribute was ignored.

The initialization benchmark compares baseline A, attribute-only candidate, and baseline B on the same runner for each framework. Decoder and benchmark sources must be byte-identical between phases. All ten single-operation rows, allocations, dispersion, and JIT listings require inspection. A candidate confidence interval wholly above both controls fails the gate. A failed measurement must not be rerun merely to obtain green. Full .NET 8 and .NET 10 test suites are also required before merge.
